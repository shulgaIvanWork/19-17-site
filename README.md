# 19×17 - сайт на React

Утвержденный дизайн (`../Meridian Site v3.dc.html`), собранный на Next.js App Router.
**Сайт русскоязычный.**

## Структура

Услуги собраны в два хаба. Решение заказчика от 2026-09-11: оставить хабы вместо
отдельных страниц услуг.

| Адрес | Что там |
|---|---|
| `/` | Главная |
| `/websites` | Хаб «Сайты»: разделы `#landing`, `#multipage`, `#marketplace`, `#redesign`, `#support`, `#onec`, `#crm` |
| `/vpn-ai` | Хаб «VPN / AI»: разделы `#vpn`, `#ai` |
| `/pricing` | Цены |
| `/about` | О компании |
| `/privacy` | Политика обработки персональных данных |
| `/api/enquiry` | Прием заявки из формы |

Шапка: Главная · Сайты ▾ · VPN / AI ▾ · Цены · О нас.

Старые адреса отдельных услуг (`/vpn`, `/ai`, `/support`, `/website-redesign`,
`/online-store`, `/integrations/crm`, `/integrations/1c`, `/integrations`,
`/maintenance`) - серверные редиректы в `next.config.ts` на разделы хабов. Сейчас это
307, пока структура может меняться; перед запуском перевести на `permanent: true`.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # продакшен-сборка
npm run lint       # eslint .
npm run typecheck  # tsc --noEmit
```

Ловушка: после удаления или переименования маршрута `tsc` ругается на старые типы в
`.next/types`. Удалите `.next`, он пересоздается при сборке.

Линтер - ESLint с конфигурацией `eslint-config-next` (`eslint.config.mjs`). Команда
`next lint` в Next 16 удалена, настройка плоская, по документации в
`node_modules/next/dist/docs`. Включены правила Next, React, хуков и typescript-eslint;
последние ловят неиспользуемый код, который `tsc` пропускает.

## Где что лежит

| Папка | Что внутри |
|---|---|
| `app/` | По папке на маршрут. `layout.tsx` - шапка, футер, провайдер формы и декор. `globals.css` - токены и общий словарь классов. `api/enquiry/route.ts` - единственный бэкенд. |
| `components/` | Компоненты по папкам-фичам, рядом с каждым его `*.module.css`. |
| `content/` | Только данные: все тексты сайта (`nav`, `products`, `pricing`, `team`, `site`, `legal`) и `settings.ts` с переключателями анимации героя. Функций и обращений к DOM здесь нет. |
| `lib/` | Код, общий для клиента и сервера: `enquiry.ts` - проверка заявки, одна для формы и маршрута API. |

Папки `components/`:

| Папка | Что внутри |
|---|---|
| `ui/` | Базовые элементы без знания о контенте: `Button`, `TextLink`, `Section`, `Overlay`, `Field`, `ChoiceRow`, `Photo`. |
| `blocks/` | Блоки страниц, собранные из данных `content/`: `ProductCard`, `PricingCard`, `CompareTable`, `NumberedClaim`, `TwoColList`, `PlanFigure`, `TeamCarousel`. Марки услуг - `CardMark` (плоские) и `PricingMark` (изометрические), общие правила их стилей - в `markBase.module.css`. |
| `contact/` | Форма заявки: `ContactContext` (провайдер), `ContactModal`, кнопки вызова, `Consent`. |
| `nav/` | Шапка, выпадающие меню, мобильное меню, переход к якорю из адреса (`ScrollToHash`, `HashLink`) и общее поведение меню (`useHoverMenu.ts`). |
| `hub/` | Навигация по разделам хаба: `HubNav` показывает `HubRail` (рельс точек на широком экране) и `HubPager` (полоса внизу на узком). Механика - `hubLinks.ts` (разбор адресов, чистые функции), `hubScroll.ts` (прокрутка, закрепление раздела, подписки) и `useHubSectionHash.ts`. Потребители не только меню: на те же события подписаны 3D-герои и сцены. |
| `hero/` | Герой и объекты в нем: компоненты и геометрия (`heroGlobe`, `heroShapes`, `heroScroll`, `heroTypes`). |
| `scenes/` | Живые сцены `AboutScene`, `BoardScene`, `PricingScene`, `BandArt` и их хуки `useSceneGaze`, `useSceneProgress`. |
| `site/` | Общие для всех страниц элементы из `layout.tsx`: `Footer`, `ClientDecor` и то, что он подгружает (`SiteMotion`, `ScrollLinkedMarks`, `ScrollToTop`). |

Правила:

- **тексты и данные - в `content/`, оформление компонента - в его модуле;**
- **файл лежит в папке фичи, которая его использует.** Хук или вычисления, нужные одной
  папке, лежат рядом с ее компонентами; в `lib/` - только то, что нужно и клиенту, и
  серверу. Внутри папки импорт `./X`, между папками `@/components/папка/X`;
- **направление импортов:** `app` → `components`, `lib`, `content`; `components` →
  `components`, `lib`, `content`; `lib` → `content`; `content` → только `content`.
  Нарушение было: тип знака карточки лежал в компоненте, и данные импортировали из
  `components/` (исправлено 2026-09-11). Второе: движок прыжков по разделам лежал в
  `components/nav`, а зависели от него герои и сцены, то есть папка меню управляла
  анимацией 3D. Вынесен в `components/hub` (2026-09-12);
- **одна разметка на обе ширины.** Блок карточек не дублируется на десктопную верстку
  и мобильную карусель: класс `rail` в `globals.css` превращает ту же сетку в
  горизонтальную ленту с примагничиванием, `railcard` дает карточке рамку. Так было в
  пяти местах, и страница цен держала в разметке 20 карточек вместо 10 (2026-09-12);
- **лента - сетка, строки карточек выравнивает subgrid.** Карточка ленты задает
  `--rail-rows` (сколько в ней строк: заголовок, линия, текст, кнопки) и берет строки
  ленты через `grid-template-rows: subgrid`; `height: 100%` у карточек не ставится, он
  отключает растяжение. Подбор `min-height` не держал: высоты карточек расходились на
  20-100px, линия под заголовком гуляла на 11px, заголовки тарифов на 18px (2026-09-13);
- **место прыжка и посадки на якорь считать на каждом кадре.** У `.section` стоит
  `content-visibility: auto`: неотрисованный раздел занимает 720px, и страница меняет
  высоту прямо во время прокрутки. Цель, посчитанная один раз, уводила прыжок по рельсу
  в футер (перелет 2325px), а переход по ссылке футера мимо раздела (до 192px). Движок -
  `components/hub/hubScroll.ts` (2026-09-13);
- **прокрутку посетителя определять по его действиям, а не по сдвигу позиции.**
  Браузер и Next прокручивают страницу сами: плавно к якорю при загрузке и при
  дорисовке разделов. Сравнение позиции принимало это за посетителя, прекращало посадку
  на якорь, и страница уезжала на 1641px. По действиям (касание, колесо, клавиша)
  устроено и направление прокрутки на телефоне в `SiteHeader.tsx`: атрибут
  `data-scroll-dir` на `<html>`, при прокрутке вверх прячется нижняя полоса, шапка не
  прячется. Направление меняется после хода 24px в одну сторону, позиция зажата в
  границы страницы, чтобы отскок у низа не прятал полосу (2026-09-13);
- **при открытом меню прокрутку держит только `<html>`.** С `overflow: hidden` еще и на
  `<body>` тот становился контейнером прокрутки, sticky-шапка уезжала, ее переводили в
  `position: fixed`, и страница прыгала вверх на 44px (2026-09-13);
- **`theme-color` не объявлять в `viewport` Next.** Тег один, его ведут скрипт темы в
  `app/layout.tsx` и `ThemeToggle`. С `themeColor` в `viewport` на странице было два
  тега разного цвета, и какой возьмет браузер, не гарантировано (2026-09-13);
- **проверка заявки только в `lib/enquiry.ts`.** Форма и API вызывают одну функцию.
  Пока проверка жила в двух местах, клиент и сервер разошлись дважды: форма отправляла
  направление, которого не было в списке сервера, а позже форма перестала проверять имя;
- новый раздел хаба = секция с `id` на странице хаба + пункт в `siteMenuGroups` или
  `infraMenuGroups` в `content/nav.ts` + направление заявки в `interestBySection` в
  `content/site.ts`.

## Решения по стеку

| Решение | Почему |
|---|---|
| Next.js 16, App Router, TypeScript | Все страницы пререндерятся в статику - это маркетинговый сайт, его должны находить. Плюс серверный маршрут для формы без второго сервиса и `next/image` для фотографий. |
| Глобальный CSS + CSS-модули | Блок `<style>` из прототипа объявлен источником истины, поэтому его словарь классов перенесен в `app/globals.css` почти дословно. Частное оформление компонентов разложено по `*.module.css`. |
| Тексты типизированными модулями | Каждый экран - это map по массиву из `content/`. Переход на CMS позже = замена модуля, а не страниц. |
| Шрифты через `next/font` | Самохостятся при сборке, к Google из браузера посетителя обращений нет. |

## Шрифты

**Заголовки - Unbounded, текст - Manrope.** Обе гарнитуры подключены через `next/font`
с сабсетами `latin` и `cyrillic`.

Universal Sans Display **снят**. У него нет ни одного кириллического глифа (0 из 66,
диапазон U+0400-04FF пуст), и это была лицензия personal-use, которую нельзя
публиковать. Файл вынесен из `public/` в `../_superseded/fonts/`, чтобы он не уезжал на
сервер. Сменить дисплейную гарнитуру - одна строка `--font-display` в `app/globals.css`.

## Отступления от дизайн-системы Showroom

Приняты заказчиком 2026-09-11. Правила Showroom («ноль теней», «ноль градиентов»,
«единственная анимация - смена цвета», «иконок нет») в этом проекте действуют с
исключениями ниже. Сверяйтесь с этим списком, а не с readme дизайн-системы:

- темная тема: переключатель `ThemeToggle`, токены в `html[data-theme='dark']` в
  `globals.css`;
- живые сцены `AboutScene`, `BoardScene`, `BandArt`, `CardMark` и объекты в героях;
- появление блоков при прокрутке (`SiteMotion`) и анимация входа страниц
  (`app/template.tsx`);
- тени и градиенты сверх двух исходно разрешенных (фон героя и подсветка курсора);
  подсветка курсора работает также на шапке и сценах;
- вес 600 и радиусы 2 и 8 px в отдельных местах;
- собственные SVG-иконки: тема, «наверх», навигация по разделам;
- метка «ХИТ!» у VPN / AI, ее текст в `content/nav.ts` (`hitBadge`).

Все анимации отключаются при `prefers-reduced-motion`.

## Что перенесено из прототипа с изменениями

- **Контейнерные запросы → медиазапросы** на тех же ширинах (1120 - шапка
  сворачивается, 1024 - `.g4` и `.gcards` в два столбца, 768 - все в один). Единственный
  контейнерный запрос оставлен на `.mediacard`: название на карточке масштабируется от
  карточки, а не от страницы.
- **`<div onClick>` → настоящие `<button>` / `<a>` / `<input>`.**
- **Форма получила ловушку фокуса, `Esc`, блокировку прокрутки и возврат фокуса.**
  При переключении на подтверждение фокус уходит на «Готово», а сам блок объявляется
  через `role="status"`.
- **Выпадающие меню шапки и навигация по разделам работают с клавиатуры**: открываются
  по фокусу, строки - ссылки, `Esc` закрывает и возвращает фокус на кнопку. По
  наведению закрытие отложено на 200 мс и отменяется возвратом курсора. Поведение
  общее, в `components/nav/useHoverMenu.ts`.
- **`hero-object.js` стал React-компонентом** (`HeroObject.tsx`), а не custom element,
  чтобы ничего не регистрировалось во время SSR. Грузится лениво. Исходник прототипа
  лежит в `../_superseded/hero-object.js`.
- **Таблицы сравнения остались сеткой `.divrow`**, а не `<table>`: под 900px строка
  превращается в карточку ленты, название столбца печатается в самой ячейке. Разметка
  при этом одна, семантику несут ARIA-роли.
- **Добавлена страница 404** - в дизайне ее не рисовали.

## Персональные данные (152-ФЗ)

Форма собирает имя, почту или телефон и направления обращения, поэтому обработка идет
по 152-ФЗ. Сделано:

- **Страница `/privacy`** - политика обработки ПДн, текст в `content/legal.ts`, ссылка в
  футере и у галочки согласия.
- **Галочка согласия в форме** (`components/contact/Consent.tsx`). Не отмечена заранее:
  предзаполненная галочка согласием не считается. Без нее форма не отправляется, а
  сообщение об этом - предложение, а не красная рамка.
- **Проверка на сервере.** `app/api/enquiry` вызывает ту же `checkEnquiry` из
  `lib/enquiry.ts`, что и форма, и отклоняет заявку без `consent: true` со статусом 400:
  клиентскую проверку можно обойти. Нативная валидация браузера выключена
  (`noValidate`); атрибуты `required` оставлены для скринридера.
- **Доказательство согласия.** Вместе с заявкой уходят `consent`, `policyVersion` и
  `consentAt`. При содержательной правке текста политики поднимайте `policyVersion` в
  `content/legal.ts`.

Что еще нужно сделать человеку, а не коду:

1. **Отдать текст политики юристу.** Это заготовка по структуре 152-ФЗ, а не
   проверенный документ.
2. **Заменить реквизиты оператора** и названия хостинга и CRM в `content/legal.ts`:
   сейчас там квадратные скобки, и они видны на странице.
3. **Дополнить разделы 3 и 6 политики**, если появятся Яндекс.Метрика, чат или пиксель:
   сейчас там написано, что аналитики и cookie нет.
4. **Уведомление в Роскомнадзор** о намерении обрабатывать ПДн подает оператор.

## Чего в дизайне нет вообще

Это не пробелы сборки: этого никто не рисовал, а для русского рынка часть обязательна.

  нарисована по присланному образцу, `app/apple-icon.png` 180px снят с нее же для iPhone.
