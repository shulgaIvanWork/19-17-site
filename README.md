# 19×17 — сайт на React

Утверждённый дизайн (`../Meridian Site v3.dc.html`), собранный на Next.js App Router.
**Сайт русскоязычный.** Двенадцать маршрутов, панель «Сайты», форма заявки с согласием
на обработку ПДн и один API-маршрут под неё.

Структура направлений (решение заказчика от 2026-09-09):

- **Сайты** — панель на шесть услуг: создание под ключ, интернет-магазин, обновление
  сайта, техническая поддержка, интеграции с CRM, интеграции с 1С.
- **VPN** — корпоративная частная сеть.
- **AI** — модель на своём железе, дообученная под компанию.

Шапка: Главная · Сайты ▾ · VPN · AI · О нас. «Цены» в шапке нет по указанию заказчика —
страница осталась, на неё ведут кнопки героев и футер.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # продакшен-сборка
npm run typecheck  # tsc --noEmit
```

Одна ловушка: не запускать `build`, пока работает `dev` — у них общая папка `.next`,
и дев-сервер начинает отдавать 500. Если это случилось, перезапустите `npm run dev`.

## Где что лежит

| Папка | Что внутри |
|---|---|
| `app/` | По папке на маршрут, в каждой `page.tsx`. `layout.tsx` — шапка, футер, провайдер формы и подсветка курсора. `globals.css` — перенесённый словарь дизайна: токены, `.btn`, `.h1`, `.g3`, `.divrow`. `api/enquiry/route.ts` — единственный бэкенд. |
| `components/` | Компоненты под именами из дизайн-системы, рядом с каждым его `*.module.css`. |
| `content/` | Все тексты сайта: `nav`, `products`, `pricing`, `team`, `site`, `legal` (политика ПДн и текст согласия), плюс `settings.ts` с переключателями анимации героя. В компонентах текста нет. |

Правило: **тексты — в `content/`, общий визуальный словарь — в `globals.css`, частное
оформление компонента — в его модуле.** Новая услуга = правка `content/` плюс одна
`page.tsx`.

## Решения по стеку

| Решение | Почему |
|---|---|
| Next.js 15, App Router, TypeScript | Все страницы пререндерятся в статику — это маркетинговый сайт, его должны находить. Плюс серверный маршрут для формы без второго сервиса и `next/image` для фотографий. |
| Глобальный CSS + CSS-модули | Блок `<style>` из прототипа объявлен источником истины, поэтому его словарь классов перенесён в `app/globals.css` почти дословно. Частное оформление, которое в прототипе было инлайном, разложено по `*.module.css`. |
| Тексты типизированными модулями | Каждый экран — это map по массиву из `content/`. Переход на CMS позже = замена модуля, а не страниц. |
| Шрифты через `next/font` | Самохостятся при сборке, к Google из браузера посетителя обращений нет. |

## Шрифты

**Заголовки — Unbounded, текст — Manrope.** Обе гарнитуры подключены через `next/font`
с сабсетами `latin` и `cyrillic`.

Universal Sans Display **снят**. У него нет ни одного кириллического глифа (0 из 66,
диапазон U+0400–04FF пуст) — на русском сайте каждый заголовок всё равно свалился бы на
Manrope. Плюс это была лицензия personal-use, которую нельзя публиковать: файл вынесен из
`public/` в `../_superseded/fonts/`, чтобы он не уезжал на сервер.

Побочные следствия замены, все в плюс: у Unbounded есть строчные, настоящие цифры и
пунктуация, поэтому заголовки набираются в обычном регистре — ровно так, как предписывает
дизайн-система. `.figure` по-прежнему в текстовой гарнитуре, как в дизайне. Сменить
дисплейную гарнитуру — одна строка `--font-display` в `app/globals.css`.

## Что перенесено из прототипа с изменениями

- **Контейнерные запросы → медиазапросы** на тех же ширинах (1120 — шапка сворачивается,
  1024 — `.g4` и `.gcards` в два столбца, 768 — всё в один). Единственный контейнерный
  запрос оставлен на `.mediacard`: название на карточке намеренно масштабируется от
  карточки, а не от страницы.
- **`<div onClick>` → настоящие `<button>` / `<a>` / `<input>`.**
- **Форма получила ловушку фокуса, `Esc`, блокировку прокрутки и возврат фокуса** —
  в прототипе этого нет. При переключении на подтверждение фокус уходит на «Готово»,
  а сам блок объявляется через `role="status"`.
- **Панель «Сайты» работает с клавиатуры**: открывается по фокусу, строки — ссылки,
  `Esc` закрывает и возвращает фокус на кнопку. Поведение по наведению как в прототипе:
  закрытие с задержкой 140 мс, отменяется возвратом курсора, путь курсора неразрывный.
- **`hero-object.js` стал React-компонентом** (`HeroObject.tsx`), а не custom element —
  чтобы ничего не регистрировалось во время SSR. Математика и константы те же. Грузится
  лениво: движок на canvas получает только главная.
- **Обе анимации героя отключаются при `prefers-reduced-motion`.**
- **Таблицы сравнения остались сеткой `.divrow`**, а не `<table>`: под 768px дизайн
  сворачивает их в два столбца. Семантику несут ARIA-роли.
- **Добавлена страница 404** — в дизайне её не рисовали.

## Персональные данные (152-ФЗ)

Форма собирает имя, рабочую почту и компанию, поэтому обработка идёт по 152-ФЗ.
Сделано:

- **Страница `/privacy`** — политика обработки ПДн, текст в `content/legal.ts`,
  ссылка в футере.
- **Галочка согласия в форме** (`components/Consent.tsx`). Не отмечена заранее —
  предзаполненная галочка согласием не считается. Без неё форма не отправляется, а
  сообщение об этом — предложение, а не красная рамка.
- **Проверка на сервере.** Клиентскую галочку можно обойти, поэтому `app/api/enquiry`
  отклоняет заявку без `consent: true` со статусом 400. Нативная валидация браузера
  выключена (`noValidate`): её пузыри — это та самая красная рамка, которой в системе нет.
  Атрибуты `required` оставлены, их читает скринридер.
- **Доказательство согласия.** Вместе с заявкой уходят `consent`, `policyVersion` и
  `consentAt` — по ним видно, кто и с какой редакцией политики согласился. При правке
  текста политики поднимайте `policyVersion` в `content/legal.ts`.

Что ещё нужно сделать человеку, а не коду:

1. **Отдать текст политики юристу.** Это заготовка по структуре 152-ФЗ, а не проверенный
   документ.
2. **Заменить реквизиты оператора** в `content/legal.ts` — сейчас там `[Наименование
   оператора]`, ИНН, ОГРН, адрес и почта в квадратных скобках, и они видны на странице.
3. **Дополнить разделы 3 и 6**, если появятся Яндекс.Метрика, чат, пиксель или конкретный
   хостинг и CRM: сейчас там написано, что аналитики и cookie нет — это правда только
   пока их действительно нет.
4. **Уведомление в Роскомнадзор** о намерении обрабатывать ПДн подаёт оператор.

## Чего в дизайне нет вообще

Это не пробелы сборки — этого никто не рисовал, а для русского рынка часть обязательна:

- Реквизиты юрлица в футере, пользовательское соглашение, уведомление о cookie
  (политика и согласие уже сделаны — см. раздел выше).
- Логотипа нет: начертание `19×17` — это набор с разрядкой `.4em`.
- Нет favicon, OG-картинок и sitemap.

## Что проверено

`npm run build` проходит, все двенадцать маршрутов пререндерятся, 404 отдаёт 404.
Проверено в браузере против спецификации:

- Сплошная сверка по всем маршрутам: непереведённых латинских слов — ноль
  (кроме намеренных CRM, VPN, AI, amoCRM, HubSpot, Salesforce, Dynamics, ERP, API, SOAP, CMS).
  `lang="ru"`, заголовки и `<title>` на русском на каждой странице.
- Гарнитуры на отрисованной странице: `.h1`, `.h2` и название карточки — Unbounded;
  `.h3`, `.body`, `.figure` — Manrope.
- Ни одной тени; градиента два, оба разрешённые (фон героя и подсветка курсора);
  все радиусы из набора {0, 4, 12, 50%}; переходы только по цвету, 0.33s.
- Панель «Сайты»: открывается по наведению и по фокусу, ширина 420px, неразрывный путь
  курсора 10px, держится 50 мс после ухода курсора и закрывается на 140 мс, текущий
  маршрут отмечен синим и `aria-current`, `Esc` закрывает.
- Точки перелома: шапка сворачивается на 1120, карточки 3 → 2 → 1, горизонтальной
  прокрутки на 375px нет.
- Форма: фокус заходит внутрь и удерживается, `Esc` закрывает, прокрутка блокируется и
  возвращается, фокус возвращается на кнопку, чипы одиночного выбора, API проверяет поля
  и отвечает ошибками-предложениями.
- Согласие: без галочки заявка не уходит и показывается текст-предложение; сервер
  отклоняет `consent: false` и отсутствие поля (400), принимает `consent: true` (200) и
  записывает `policyVersion` и `consentAt`; галочка не отмечена по умолчанию, связана с
  подписью через `label for`, доступна с клавиатуры, 20×20 с радиусом 4 и на 375px не
  ломает вёрстку.
